## 2. 功能需求骨架

### F1 领域 schema 层（L0）

- **描述**：声明式定义井/井筒/传感器通道/生产台账的实体、字段、单位制、引用关系；场景配方（recipe）声明"生成什么场景"。
- **验收草案**：schema 文件可被加载校验；单位制显式声明；一个 recipe 描述可复现一次生成。
- **依赖**：无（根）。
- **开放问题**：格式自研 DSL 还是复用 SDV metadata 风格（charter §4）。

### F2 规则打底生成器（L1）

- **描述**：实体字典（井名/设备型号/故障代码/作业类型）+ 字段填充；扩展 faker/mimesis 的油气 locale。
- **验收草案**：M1 tracer bullet 内零手写数据。
- **依赖**：F1。

### F3 物理引擎适配层（L2）

- **描述**：油藏模拟器（首选待拍板 Q3）以**独立进程/命令行**方式集成，扫参编排产出生产时序骨架；GPL 组件不链接源码。
- **验收草案**：适配器可批量跑 N 个方案并回收结果；宿主进程与模拟器进程隔离。
- **依赖**：F1；算力成本实测（charter Q8）。

### F4 噪声/工况注入器（L2/L3 之间）

- **描述**：在物理骨架上叠加真实工况扰动——传感器漂移、缺测、坏点、量程截断、停机事件、（候选）段塞流振荡。
- **验收草案**：扰动类型可配置、可复现（种子固定）；注入前后数据均可追溯。
- **依赖**：F3。

### F5 统计/深度生成补分布（L3）

- **描述**：在物理骨架上学习残差分布、丰富场景多样性；生成器可插拔（fg-data-synthetic / mostlyai / synthcity 同接口）。
- **验收草案**：至少两种生成器通过同一接口互换，不改变下游。
- **依赖**：F1/F4。
- **开放问题**：SDV（BUSL-1.1）是否进内部实验白名单（charter §5 允许，需 Owner 确认）。

### F6 LLM 文档层（L4）

- **描述**：把结构化事实叙述化为完井报告/班报/故障工单；产出过 schema/规则校验回流，不合格重生成。
- **验收草案**：文档中的数值/日期/井号与结构化源一致（抽查可机判）。
- **依赖**：F1/F2；模型选型（charter Q7）。

### F7 评估闸门（L5）

- **描述**：三族指标——质量（SDMetrics 式）、隐私（anonymeter 三类攻击）、**物理一致性（自研：物质平衡、传感器量程/采样率合法性、递减率范围）**；输出 JSON/HTML 报告。
- **验收草案**：指标为插件；任何生成物必须过闸门才能出库。
- **依赖**：F1（指标定义挂在 schema 上）。
- **注**：物理一致性族为差异化卖点，无现成开源（调研报告 §3.3）。

### F8 输出交换层

- **描述**：Parquet/CSV 输出 + 元数据（生成参数、种子、schema 版本、数据为合成的声明）；字段命名参考 WITSML/PRODML（对齐深度待拍板 Q4）。
- **验收草案**：输出自描述——只拿输出文件能还原生成配置。
- **依赖**：F1。

### F9 CLI / 交互形态

- **描述**：v1 先 CLI（`fieldforge generate --recipe ... --seed ...`）；API/UI 后置。
- **验收草案**：M1/M2/M3 全部验收物由 CLI 驱动。
- **依赖**：跟随各里程碑。

### F10 文档与合规声明

- **描述**：README/输出元数据/评估报告三处强制"合成数据"声明与用途红线（禁止储量申报/生产决策）。
- **验收草案**：红线缺失 = 验收不通过。
- **依赖**：无。
