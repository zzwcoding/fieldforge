# S1-4 · 质量闸门——25 项检查怎么查，"没过闸不出库"是不是真的

- ✅ S1-1 发一条生成命令
- ✅ S1-2 配方文件与表结构

## 三问

**这一步干嘛？**
看懂数据出厂前的最后一道工序：质量闸门。它对每批新生成的数据跑 25 项检查，结果记进 manifest（S1-3 你见过那行 `19 通过 / 6 没启用`）。这课把 25 项是什么、6 项为什么没启用、"没过闸不出库"是真是假，一次讲完。

**为什么闸门嵌在生成里，而不是造完再补检？**
因为造数机器本质是"按规则抽签的程序"——参数设错、代码有 bug，它也会一本正经地产出整批垃圾，而且看起来像模像样。所以检查必须长在生产线上：**每批造完立刻查，不合格当场扣下**，而不是等下游用的时候才发现。

**这一步解决什么麻烦？**
解决"谁来监督造数机器"。合成数据最大的风险不是"它是假的"（它自称是假的），而是"它是假得离谱的"——日产油 5000 吨、含水 150%，这种数据流进训练或演示，丢的是整个平台的信誉。闸门就是那个监督者。

## 一、25 项检查，四个家族

对干净数据（tpa_s1_demo）跑一次评估（下一节教你自己跑），拿到的是这样一张成绩单（表里列的是代表项；合计 25 项 = 质量 3 + 隐私 3 + 物理 5 + 平台规则 14，其中平台规则 14 = r1~r12 十二条 + 受效关系劈分 1 条 + "规则 13–20"打包 1 条）：

| 家族 | 检查项 | 例子 |
|---|---|---|
| 质量（q1–q3，共 3 项） | 数据自己像不像话 | 行数跟 manifest 对得上、数值列没有"全是同一个数"的退化 |
| 隐私（p1–p3，共 3 项） | 会不会泄密 | 主键没有重复、数值组合不撞车 |
| 物理（f1–f5，共 5 项） | 符不符合油田物理 | 物质平衡（液量=油量+水量对得上账）、停机时产量必须为 0、传感器读数在量程内 |
| 平台规则（共 14 项） | tpa 平台定的 12 条业务规则等 | 井号+日期唯一、日产油非空率 ≥99.5%、计量和化验的含水差 ≤5 个百分点、区块月度物质平衡偏差 ≤3% |

干净数据的实测结果：**19 项通过、0 警告、0 不通过、6 项没启用**。

## 二、6 项"没启用"——不装查过，是种诚实

6 项 skipped 不是检查失败，是**没条件查，如实报告没查**。每项都写了原因，挑三条原文：

- 参照分布对比：`未提供 --reference；接入真实锚点后同路径即为真质量评估`——没有真实数据当参照（锚点就是"用来对照的真实样本"），比不了；
- anonymeter（一个隐私测试工具）三类攻击：`需真实参照数据（--real）；全合成场景`——隐私攻击测试的本质是"从假数据里能不能认出真人"，没有真人可认，查了也没意义；
- 规则 13–20：`待提取件二核对后启用`（提取件=平台规则源的整理文档）——平台规则后 8 条还没定稿，不硬造。

manifest 把"查过"和"没查"分得清清楚楚——**宁可记"没查"，不冒充"查过"**，这份诚实本身就是质量检查的一部分。

## 三、两种闸门模式：强制出库 vs 报告放行

配方里 gate 有个 `enforce` 开关（S1-2 你见过），决定"不合格时拦不拦"。服务器上正好有一对活教材：

**教材 A：干净数据，`enforce: true`（强制模式）**
19 项全过 → 闸门放行 → HTTP 200，数据出库。强制模式下"过了才出库"。

**教材 B：脏数据配方 tpa_s1_dirty，`enforce: false`（报告模式）**
你发这条命令试试（约 30 秒；`-X POST` 是"提交一个任务"，S1-1 用过）：

```bash
curl -X POST http://8.163.33.135/api/generate \
     -H "Content-Type: application/json" \
     -d '{"recipe": "tpa_s1_dirty"}'
```

意外吗？它也返回 200、数据照样出库——但打开 manifest 看 gate：`9 通过 / 1 警告 / 9 不通过，overall: fail`（同样是那 6 项没启用，25 = 9+1+9+6）。**闸门认认真真查了、实实在在判了不合格，但配方关了"拦截"开关（这就是报告模式），放它出库。**

为什么敢这么设计？因为这个配方的目的就是**故意造一批不合格数据**：它注入 A/B 班重复、单位误录、旧井号这些坏特征，给平台的 12 条规则当"挂科样本"用（S2 整课讲怎么造的）。配方注释里每个注入器后面就标着它对应挑战哪条规则。闸门的报告恰好就是这批数据的**出厂合格证反面**——它证明了"挂科样本真的挂科"。

**对脏数据跑评估，看闸门挑出的 9 处毛病**（run_id 在刚才返回的 `run_id` 字段里，忘了就去历史列表找）：

```bash
curl -X POST http://8.163.33.135/api/evaluate/<刚那次dirty的run_id> -o evaluation_dirty.json
```

实测挑出（原文摘录，`←` 后面是它对应的坏特征）：

```
fail  p1   主键重复率               ← A/B 班造的重复行，直接被抓
fail  r1   规则1 (well_id,prod_date) 唯一性   ← 同井同日两行
fail  r3   规则3 单位一致性           ← 油量误录成方
fail  r4   规则4 计量 vs 化验含水      ← 化验打架
fail  r6   规则6 批次水位 ≤T-1        ← T-3 补录批次（T-3=三天前；把三天前的数当成新数据补录进来）
fail  r7   规则7 井号归一化           ← 旧井号混入
fail  r8   规则8 停机原因码映射        ← 旧编码混入
fail  r9   规则9 状态机合法迁移        ← 状态滞后
warn  r10  规则10 恒值 30 日告警       ← 仪表卡死特征（告警级）
fail  r12  规则12 区块月物质平衡       ← 连坐：日报被改，月度账对不上（连坐=一处动手、处处牵连）
```

一一对上，没有一个误报。**S1-1 讲过"数字互相咬合"，这里看到它的另一面**——注入器只改了日报，月度结算是日报汇总出来的，账立刻对不上，r12 当场抓住。

## 四、"没过闸不出库"是真的吗——代码证据 + 一句实话

强制模式下不过闸会发生什么，代码说了算（`fieldforge/fieldforge/serve/app.py:93-97`）：

```python
rc = cli_main(argv)          # 生成跑完，rc 是"考试得分"：0=过，非 0=没过
if rc != 0:                  # enforce 闸门拦截等
    return JSONResponse(status_code=409, ...)   # 返回 409 + 检查报告，数据不出库
```

翻译：闸门不过 → 生成程序退出码非 0 → 接口把你的请求拒了（409），只给你看检查报告，不给你数据。

**一句实话**：这条拦截路径在这台服务器上还没有真实发生过一次——现有配方一个必过（enforce+全过）、一个故意放行（report-only）。它是装好的安全网：哪天有人写了个新配方、参数设错造出物理离谱的数据还开着 enforce，闸门当场扣下，垃圾数据到不了任何人手里。你以后在 S2 会看到那批挂科样本的详细玩法。

**四种结局一张表**（对照 runs 列表里你见过的 8 条记录）：

| gate 结果 | enforce | 结局 | 服务器上的例子 |
|---|---|---|---|
| pass | true | 出库 | tpa_s1_demo 全家 |
| fail | false | 出库，manifest 记 fail（挂科样本） | tpa_s1_dirty |
| fail | true | 409 拒绝，不出库 | 尚无实例（安全网待命） |
| not-run | — | 配方没开闸门，如实记"没跑" | one_well_365d 全家 |

顺带分清两个长像的词：**skipped** 是闸门跑了、但某一项没条件查（第二节那 6 条）；**not-run** 是闸门整个没跑（配方没配 gate）。一个是"考了但有题没做"，一个是"压根没进考场"。

**闯关答案（做完题再看）**

**捣乱实验 2 的答案**：闸门照样 9 挂，但这次会拦——生成程序退出码非 0，接口返回 409，挂科样本出不了库。所以脏配方必须配报告模式：它的价值就在"带着 fail 记录出厂"，强制模式反而把它掐死了。

1. 区别在闸门 fail 之后听谁的：`enforce: true` 是强制模式——fail 就拦截，数据不出库，适合"交付给下游正常使用"的批次；`enforce: false` 是报告模式——fail 照样出库，但 manifest 里记上 fail，适合"这批数据本身就是挂科样本"的批次（脏数据的价值恰恰在于它的 fail 记录）。一句话：**交付的数据用强制，考题的数据用报告**。
2. 因为隐私攻击的题目就是"从合成数据里能不能认出真人"：拿真实数据当对照，试看能不能从假数据里把某个真人的特征指认出来（认出=泄密）。全合成场景里压根没有真人，"认出真人"这件事无从发生，检查没有对象——所以如实 skipped，而不是硬跑一个没有意义的检查。
3. 连坐。注入器动的是日报表（恒值 30 日、单位误录这些都改了产量数字），而月度结算表是按日报汇总出来的——日报被改，汇总的账就跟区块的物量平衡对不上了。闸门查的是"账账相符"，不管你是有意改的还是 bug 改的，改了账它就报。这正是数据咬合的价值：单独看一列未必发现，交叉对账就现形。
